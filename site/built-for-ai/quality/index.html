Built for AI

Quality bar.

The definition of done for every change that touches the design system or consumes it. An AI agent's job is not finished until this checklist passes.

Canonical version: docs/ai/quality-bar.md.

The checklist

Grouped by concern — tokens, components, modes, states, accessibility, code quality, tests, bundle, documentation. Each item is a yes/no check, not a discussion. Full list mirrored from the canonical doc.

Tokens

  • No hardcoded colours, sizes, radii, durations, shadows.
  • Visual values come from semantic or component tokens.

Components

  • Every UI element is a Kijani component or a documented composition.
  • No detached / forked / locally-redefined logic.
  • Props match the documented API.

Modes

  • Light and dark render correctly.
  • RTL: no left / right properties.

States

  • Default, hover, focus, disabled, loading, empty, error — all covered.

Accessibility

  • axe-core: zero violations.
  • Keyboard reachable + operable.
  • Screen reader: labels, roles, state changes announced.
  • Colour contrast meets WCAG AA in every mode.
  • prefers-reduced-motion respected.

Code quality, tests, bundle, docs

Detail mirrored in the canonical doc. Strict types, behaviour-based tests, Storybook story + Chromatic snapshot, bundle impact noted, changelog written.

How AI self-runs the checklist

A short prompt fragment AI can append to any task: run the checklist on the code you just produced, report pass / fail / not-applicable per section with one sentence of evidence, no "looks good" summaries.

When a check legitimately fails

Name the exception in the PR description. Anything not named is taken as missed.
