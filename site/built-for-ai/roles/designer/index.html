Built for AI · Role guide

For designers.

Your two-minute orientation. You'll spend most of your AI time on intent-to-frames and on handoff specs. The Figma library is your source of truth; AI plugs into it, not around it.

Canonical version: docs/ai/roles/designer.md.

The shape of your day with AI

  1. Intent to frames

    Cowork / Lovable produce rough flows from prose — argue with yourself before committing.

  2. Compose inside Figma

    Stay inside library components + Variables. The plugin keeps it in sync with code.

  3. Write specs for handoff

    AI turns finished frames into the written spec a dev needs.

What "library-clean" frames look like

  • Every element is a library component instance.
  • Every visual value is a Variable / Text Style.
  • Light and dark switch correctly.
  • Zero detached instances.
  • Empty / loading / error / RTL frames present.

Templates you'll use most

  • Turn this Figma frame into a spec
  • Explore a flow
  • Generate a component variant (when proposing a library change)

Full text in the prompt library.

How AI reads your work

Devs' AI agents read your spec first and your frames second. If the spec is sparse, the AI fills the gaps with guesses. Spend the time on the spec.

Anti-patterns

  • Designing pixel-perfect mocks of components that already exist.
  • Specifying colours by hex instead of by Variable.
  • Treating an AI prototype as the design.
  • Annotating prop values as colours / sizes rather than prop names.

What to escalate, and to whom

Missing variant → RFC, both leads review. Token feels off → PR against src/tokens/source/. Doesn't fit any component → don't fork; propose the component.
