# docs/ai/ — AI usage guides

Deep-dive companion docs to the root [`CLAUDE.md`](../../CLAUDE.md). Each file in this folder is referenced from CLAUDE.md and exists to keep the front door short.

| File | Audience | What it answers |
|---|---|---|
| [`pipeline.md`](./pipeline.md) | Everyone | How does an idea become shipped code? Who's responsible at each stage? Where does AI plug in? |
| [`component-usage.md`](./component-usage.md) | Devs + AI agents | Which component for which case? How to compose? What never to do? |
| [`token-usage.md`](./token-usage.md) | Devs + AI agents | Which token tier? When can I escape to a primitive? What's never allowed? |
| [`prompting.md`](./prompting.md) | Everyone | Reusable prompts per role and per task. Templates that produce good output reliably. |
| [`quality-bar.md`](./quality-bar.md) | Reviewers + AI agents | The checklist every change has to pass before merge. |
| [`roles/pm.md`](./roles/pm.md) | Product managers | Prompt-to-app flows, scoping, escalation. |
| [`roles/designer.md`](./roles/designer.md) | Designers | Figma workflow, Variables / modes, design-to-AI handoff. |
| [`roles/developer.md`](./roles/developer.md) | Developers | Claude Code workflow, PR conventions, review. |

The same content is published in human-readable form at [`site/built-for-ai/`](../../site/built-for-ai/) (the showcase site).
