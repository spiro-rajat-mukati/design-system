How this came to be, who owns it, and how it evolves.

What this is

The Kijani Design System is the shared visual language and component library used across Kijani's product surfaces. It exists so designers and engineers can build product faster, consistently, without re-inventing the same button or form for every feature.

How it's built

One source repository on GitHub holds every artifact — tokens, components, documentation, the Figma plugin, this site. Tokens are authored once as W3C JSON; a build script generates the CSS, TypeScript, and Figma Variables representations. The Figma library is kept in sync by a custom plugin that pulls from the same source.

Ownership

The design system is owned jointly by the design lead and the engineering lead. Both must sign off on any token addition, component addition, or breaking change. Anyone on the Kijani team can propose changes; the leads triage and approve.

Versioning

Semver discipline:

  • Major — breaking changes (component API changes, removed tokens, renamed Variables).
  • Minor — new components, new tokens, new variants.
  • Patch — bug fixes, value tweaks (e.g. nudging a colour hue), documentation.

License

Internal to Kijani. The source repository and this site are private to the team.

How to contribute

See Resources for the contribution flow. Token tweaks and bug fixes start as GitHub issues or PRs; new components require an RFC.
