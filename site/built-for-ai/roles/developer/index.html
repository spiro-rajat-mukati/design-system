The shape of your day with AI

  1. In-repo builds

    Claude Code implements specs against the library when given CLAUDE.md + the component-usage doc.

  2. Refactors and migrations

    Claude Code is excellent at sweeping changes when scope is explicit.

  3. Review and self-review

    Run the quality bar checklist on your diff before requesting human review.

Setting up Claude Code for this repo

  1. Clone the repo and cd in.
  2. Confirm CLAUDE.md is at the repo root.
  3. Start a session in this directory — Claude Code reads CLAUDE.md automatically.
  4. Run the /init skill once for long sessions.
  5. Run /review on your branch before pushing.

Templates you'll use most

How to write prompts Claude Code executes well

  • Demand a plan before code — components + tokens it'll use.
  • Constrain the diff — name the paths to modify.
  • Reference files by path, not name.
  • Ask for tests in the same turn.
  • End every prompt with the self-check against the quality bar.

What Claude Code is bad at

  • Architecture decisions across the system — that's an RFC.
  • Long-running refactors without checkpoints — chunk by PR.
  • Visual judgement — run Chromatic and look.

Anti-patterns

  • Letting the agent introduce a dependency without confirming.
  • Accepting an implementation that "looks fine" without the quality-bar checklist.
  • Skipping the Storybook story update — it's part of the change.

What to escalate, and to whom

Token change → both leads review the PR. Component API change → RFC, both leads sign off. Cross-cutting change → schedule a sync.
