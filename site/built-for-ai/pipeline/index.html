Built for AI

Design-to-dev pipeline.

How an idea becomes shipped, production-ready code at Kijani — and where AI plugs in at each stage. This is the workflow every Kijani project follows, regardless of who started it.

The canonical version of this workflow lives in the repository at docs/ai/pipeline.md — the same file AI agents read when they join a session. This page mirrors it for humans.

The seven stages

Each stage names the human owner, what the AI is reading, the deliverable, and the gate to the next stage.

  1. Intent

    Owner: PM. AI reads: role guide for PMs, prompt library. Deliverable: one-pager (problem · user · success). Gate: sharp enough that a designer can sketch without follow-up.

  2. Shape

    Owner: PM + designer. AI reads: prompt library, Lovable / Cowork templates. Deliverable: low-fi flow. Gate: testable on the team before pixels.

  3. Design

    Owner: designer. AI reads: component usage, token usage, designer role guide. Deliverable: Figma frames built entirely from Kijani library, all modes + states covered. Gate: zero detached instances, zero hardcoded values.

  4. Spec

    Owner: designer (with AI assistance). AI reads: component usage, quality bar. Deliverable: written spec listing components, prop values, states, accessibility intent. Gate: concrete enough that a dev can build without guessing.

  5. Build

    Owner: developer + Claude Code. AI reads: the whole docs/ai/ tree, existing component code, token files. Deliverable: PR with code + stories + tests + Chromatic snapshot. Gate: quality-bar checklist passes end-to-end.

  6. Review

    Owner: design + eng leads jointly. AI reads: quality bar, /review + /security-review slash commands. Deliverable: approval (or RFC if scope grew). Gate: both leads sign off; Chromatic baseline updated.

  7. Ship + observe

    Owner: developer. AI reads: changelog template. Deliverable: release notes, version bump. Gate: visible in Storybook + showcase site within 24 hours.

Anti-patterns

  • Skipping the Spec stage — AI builds against vibes and ships subtle drift.
  • Treating Design as optional because "we have AI" — without a library-clean Figma file, there's no source of truth.
  • Generating Build code without reading the component-usage contract first.
  • Approving a Review because the diff "looks fine" — unintended Chromatic changes mean the build isn't ready.
