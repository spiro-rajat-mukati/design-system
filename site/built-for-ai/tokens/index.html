Token usage.

The contract for visual values. No hardcoded colours, sizes, radii, durations, or shadows — ever. This page explains the tier system, when each tier is appropriate, and the anti-patterns that creep in when nobody's looking.

Canonical version: docs/ai/token-usage.md.

The three tiers

primitive → semantic → component. Primitives are raw values; semantics are intent-bound and rebind per mode; component tokens are per-component slots. Full explanation in the canonical doc.

Which tier to use

Four-question decision tree to pick the right tier. To be mirrored.

Anti-patterns

  • Hex colours in CSS — use the semantic token.
  • Pixel spacing — use the spacing scale or a layout primitive.
  • Hardcoded radius / shadow / duration — every visual value has a token.
  • Referencing a primitive directly from a component — go through a semantic.

Modes, RTL

Modes (light / dark) rebind at the semantic tier. RTL uses logical CSS properties only — never left / right. Touch-target sizing lives in the mobile (React Native) tokens, not a web density mode. Detail in the canonical doc.

When you need a new token

New primitives are rare; new semantics happen most weeks. File the change against src/tokens/source/ — never against generated files.

How AI agents query token availability

Grep src/tokens/source/ for the intent name. If nothing matches, the token doesn't exist — propose it, don't invent it in CSS.
