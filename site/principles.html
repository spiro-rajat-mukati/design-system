Principles

What we
believe.

What we believe about how a design system should work, and the decisions that flow from those beliefs. If a contribution disagrees with one of these, we'll have a conversation.

01

Tokens are the contract

Every visual value lives in a token. If a value isn't a token, it's a bug. The token is the shared agreement between design and engineering — when it changes, it changes everywhere, in one motion. No raw hex, no magic numbers in component CSS or Figma fills.

02

Composition over configuration

A Field that takes <Input /> as a child beats a Field with twenty input-related props. Slots scale to whatever content a team needs; prop sprawl doesn't. When in doubt, design the API around children, not properties.

03

Light and dark are first-class

Not bolted on. Every component is built knowing it will render on a light background and a dark background. The token system handles the swap; components don't ship until both look right. Touch-target sizing lives in the mobile (React Native) tokens, where iOS and Android are separate platforms.

04

Accessibility is the floor, not the goal

WCAG 2.1 AA contrast on every state. Visible focus on every interactive element. Keyboard parity with mouse. RTL-safe via logical properties. Reduced-motion honoured. These aren't features — they're the baseline. If a component doesn't meet them, it doesn't ship.

05

The system is a product

It has users — every team that consumes it. It has a roadmap. It has versioning, changelogs, and breaking-change discipline. Treat the system the way you'd want any vendor to treat the libraries you depend on.

06

Prefer the boring choice

A new pattern means an RFC, design review, code, documentation, Figma, and migration. Use what's already in the library unless there's a strong reason not to. New entries get added when product needs force it, not when product teams ask for novelty.

07

One source of truth, multiple targets

Tokens are authored once, in JSON. CSS, TypeScript, and Figma Variables are generated. No one edits the generated files. The discipline is what keeps the system from drifting — and what makes "change once, applies everywhere" a property of the system, not aspirational marketing.
